---
title: Use git worktree instead of stashing
date: "2026-08-01"
category: Tech
summary: Need to fix a bug while mid-feature? `git worktree add ../repo-hotfix main` gives you a second working directory on its own branch — no stashing, no half-done commits, no losing your editor state. Work on both in parallel, then `git worktree remove` when done.
---

`git stash` is where uncommitted work goes to be forgotten. Worktrees solve the same problem without hiding anything.

A worktree is an extra working directory attached to the same repository — same objects, same remotes, its own checked-out branch:

```bash
# you're mid-feature in ~/dev/robot-sim, and a hotfix request lands
git worktree add ../robot-sim-hotfix main

cd ../robot-sim-hotfix   # clean checkout of main
# fix, commit, push, open PR

git worktree remove ../robot-sim-hotfix
```

Your feature directory never changed: editor buffers, virtualenv, build artifacts, running processes — all untouched.

Other places worktrees shine:

- **Reviewing a PR properly** — check the branch out in a worktree and run it, without disturbing your own work.
- **Long-running experiments** — keep a training run going from one worktree while you develop on another branch.
- **Comparing two versions side by side** — two directories beat flipping a single checkout back and forth.

`git worktree list` shows what's active. The one rule: a branch can only be checked out in one worktree at a time.
